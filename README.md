# Local 2FA Authenticator

Локальный TOTP-аутентификатор для Chrome на Windows. Коды двухфакторной аутентификации, импорт QR и автоматическая вставка на выбранных сайтах — с зашифрованной базой в отдельном переносимом файле.

**Без облачной синхронизации и аналитики.** Ключи, QR-коды и изображения обрабатываются на устройстве.

[Установка и использование](INSTALL.md) · [Релизы](https://github.com/asemenov566/local-2fa-topt-chrome-app/releases) · [Сообщить об ошибке](https://github.com/asemenov566/local-2fa-topt-chrome-app/issues)

## Возможности

| Возможность | Что доступно |
| --- | --- |
| Коды TOTP | SHA-1, SHA-256 и SHA-512; 6 или 8 цифр; настраиваемый период |
| Быстрый доступ | Копирование по нажатию, поиск, компактные строки или плитки, изменение порядка |
| Интерфейс | Мини-попап и отдельное окно, светлая и тёмная темы |
| Добавление | Ввод ключа или `otpauth`-ссылки, QR из файла, буфера, камеры или текущей вкладки |
| Перенос | Многочастный QR Google Authenticator, пропуск дубликатов с сохранением локальных имён |
| Экспорт | Зашифрованная копия, открытые JSON/TXT, групповые QR Google и QR отдельных аккаунтов |
| Автоустановка | Госуслуги и указанный пользователем HTTPS-сайт Битрикс, после действия входа |
| Разблокировка | Код-пароль, совместимый passkey или автоматическое открытие на этом ПК |

## Быстрый старт

Требуются **Windows**, **Chrome 120 или новее** и **.NET Framework 4.x** для локального помощника. Node.js для установки готового приложения не нужен.

1. Скачайте архив приложения из [релиза](https://github.com/asemenov566/local-2fa-topt-chrome-app/releases) и распакуйте в постоянную папку.
2. Запустите `Install-Windows.cmd` — установка выполняется для текущего пользователя, без прав администратора.
3. Откройте `chrome://extensions`, включите режим разработчика и загрузите папку `extension` через «Загрузить распакованное расширение».
4. Откройте значок расширения, задайте код-пароль и добавьте аккаунты.

Пошаговая инструкция, перенос базы и решение проблем — в [INSTALL.md](INSTALL.md).

## Хранение и защита

После первого задания пароля приложение создаёт файл `%USERPROFILE%\.CHROME-APP-TOTP.vault`. Расположение меняется в настройках. Для переноса на другой ПК достаточно файла базы и его пароля.

База **всегда зашифрована**: AES-256-GCM, PBKDF2-SHA256 с 600 000 итераций, случайная соль 128 бит и новый IV 96 бит при каждом сохранении. Проверка целостности охватывает содержимое и метаданные версии записи, соли и длины пароля. Открытый пароль в файл и настройки Chrome не записывается.

| Режим | Как работает |
| --- | --- |
| По умолчанию | Код-пароль из 4 или 6 символов; ключ открытой сессии хранится в доверенном хранилище сессии Chrome |
| «Не запрашивать пароль» | Производный ключ защищается Windows DPAPI для текущего пользователя; его защищённая копия позволяет открывать базу после перезагрузки ПК |
| Ключ доступа | Совместимый WebAuthn PRF passkey защищает дополнительную копию ключа; пароль остаётся способом переноса и восстановления доступа |

Выключение автоматического открытия удаляет сохранённую копию ключа и блокирует приложение. Смена пароля перешифровывает базу, обновляет ключ автоматического открытия и сбрасывает привязку passkey.

> **Границы защиты:** короткий код-пароль можно подобрать к украденной копии файла. Блокировка на минуту после трёх ошибок действует только внутри приложения. DPAPI не защищает от программы, работающей с правами вашего пользователя Windows. Открытый экспорт и QR содержат секретные ключи аккаунтов.

Делайте резервные копии файла. Старые копии сохраняют прежний пароль. Одновременное редактирование одной базы на нескольких ПК не поддерживается.

## Автоустановка и нагрузка

Автоустановка выключена по умолчанию. После привязки аккаунта расширение запрашивает доступ только к выбранному сайту. Обработка начинается после действия входа; ожидание поля TOTP ограничено 15 секундами. Расширение вставляет код, но само не отправляет форму.

Фоновый обработчик работает по событиям, без постоянного опроса вкладок и файлов. Выключение автоустановки снимает обработчики страниц. Таймеры кодов обновляются только при видимом интерфейсе; камера и распознавание работают только во время сканирования. Локальный помощник завершается после операции — постоянной службы нет.

## Разрешения Chrome

| Разрешение | Назначение |
| --- | --- |
| `storage` | Настройки, метаданные и ключевые материалы согласно выбранному режиму |
| `nativeMessaging` | Доступ к файлу базы и защита локального ключа через Windows DPAPI |
| `clipboardWrite` | Копирование кода или секретного ключа по действию пользователя |
| `activeTab` | Снимок текущей вкладки для импорта QR |
| `scripting` | Автоустановка на сайтах, которым пользователь разрешил доступ |
| Необязательный доступ к HTTPS-сайтам | Возможность привязать свой Битрикс; фактический доступ выдаётся отдельно для выбранного адреса |

Камера запрашивается отдельно при сканировании. Библиотеки и QR-декодер включены в расширение; внешние CDN не используются.

## Разработка

Нужен Node.js 20 или новее. Команды выполняются из корня проекта:

```powershell
npm ci
npm test
npx playwright install chromium
npm run test:browser
npm run test:native
```

Браузерные тесты используют синтетические данные и отдельные профили в `work/`, включая изолированный `USERPROFILE`. Свой тестовый браузер можно указать через `TOTP_CHROMIUM_PATH`. Интеграционная проверка `npm run test:native:browser` дополнительно требует зарегистрированного Native Messaging помощника.

| Команда | Назначение |
| --- | --- |
| `npm run build:native` | Пересборка Windows-помощника из C# |
| `npm run build:vendor` | Сборка локальных библиотек из зафиксированных зависимостей |
| `npm run build:icons` | Генерация иконок расширения |
| `npm run build:release` | Архив приложения и SHA-256 в `outputs/` по явному списку файлов |

Исходники расширения находятся в [extension](extension/), Windows-помощника — в [native](native/), проверки — в [tests](tests/). Публичный `manifest.key` сохраняет ID распакованного расширения; это не секретный ключ подписи.

## Совместимость

- Поддерживается TOTP; аккаунты HOTP со счётчиком не импортируются.
- Синхронизации с облаком Google Authenticator нет.
- Для passkey требуется поддержка WebAuthn PRF конкретным провайдером. Наличие Windows Hello само по себе её не гарантирует.
- Формат группового QR Google не передаёт нестандартный период TOTP. Для таких записей используйте одиночный QR. Совместимость группового экспорта с Apple Passwords не подтверждена.
- Системное время должно быть точным; приложения-получатели могут не поддерживать нестандартные параметры TOTP.
