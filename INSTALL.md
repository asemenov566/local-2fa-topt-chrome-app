# Установка Local 2FA Authenticator

Local 2FA Authenticator — локальный аутентификатор для Google Chrome на Windows. Коды и настройки аккаунтов хранятся в зашифрованном файле; облачная учётная запись для работы приложения не нужна.

## Требования

- Windows и Google Chrome версии 120 или новее.
- Windows PowerShell и .NET Framework 4.x. Если готового файлового помощника нет, установщик соберёт его штатным компилятором .NET Framework.
- Полная папка приложения, включая `extension`, `native` и `Install-Windows.cmd`.

Node.js, npm и права администратора для обычной установки не нужны. Камера нужна только для сканирования QR с камеры; вместо неё можно импортировать изображение или ввести ключ вручную.

## Установка

1. Распакуйте архив целиком в постоянную папку. Не запускайте приложение прямо из архива и не оставляйте его во временной папке.
2. Запустите `Install-Windows.cmd`. Дождитесь сообщения об установке файлового помощника для текущего пользователя Windows.
3. В Chrome откройте `chrome://extensions` и включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное расширение** и выберите подпапку `extension`, а не корневую папку приложения.
5. Откройте Local 2FA Authenticator через меню расширений Chrome. При желании закрепите его значок на панели браузера.

Установщик регистрирует файловый помощник только для текущего пользователя Windows. Помощник запускается на время операций с файлом или защищённым ключом; служба и задание автозапуска не создаются. Папка приложения должна оставаться доступной после установки.

## Первый запуск

1. Выберите длину мастер-пароля: **4, 6 или 12 символов**. Разрешены любые символы.
2. Введите пароль и повторите его по приглашению приложения. Допускаются не только цифры; длина считается по кодовым точкам Unicode, поэтому составной эмодзи может занимать несколько символов.
3. После подтверждения приложение создаст базу:

   ```text
   %USERPROFILE%\.CHROME-APP-TOTP.vault
   ```

Если по этому пути уже есть база, приложение предложит открыть её паролем, а не перезапишет новой. Другой файл можно выбрать в настройках, в разделе **Файл базы**.

Файл базы всегда зашифрован AES-256-GCM. Короткий пароль, особенно цифровой PIN, имеет ограниченную стойкость к перебору украденной копии файла. После трёх неверных попыток приложение блокирует ввод на минуту, но это ограничение не защищает от перебора вне приложения. Храните мастер-пароль отдельно от резервной копии.

## Добавление и использование кодов

Нажмите **Добавить код** и выберите способ:

- **Ввести ключ настройки** — указать сервис, аккаунт, секрет Base32 и параметры кода.
- **QR из файла или скриншота** — выбрать или перетащить файл, вставить изображение через `Ctrl+V`. Здесь же можно импортировать резервную копию.
- **С текущего экрана** — распознать QR на активной вкладке Chrome.
- **Сканировать камерой** — разрешить доступ к камере и показать QR целиком.
- **Вставить otpauth-ссылку** — вставить ссылку настройки или переноса.

Проверьте распознанные аккаунты и подтвердите сохранение. Если экспорт Google Authenticator состоит из нескольких QR, считайте все части: после каждой используйте **Сканировать следующий QR**. Повторный импорт пропускает совпадающие секреты и сохраняет локальные имена аккаунтов.

Нажатие на текущий код копирует его. Шестерёнка аккаунта открывает редактирование и привязку сервиса; удаление требует подтверждения. Для переноса на телефон используйте передачу через QR. QR и скопированный секрет позволяют генерировать коды аккаунта — передавайте их только своему аутентификатору.

## Настройки

Через шестерёнку в верхней части приложения доступны:

- **Изменить порядок**, **Вид кодов** и **Оформление** — порядок аккаунтов, строки или плитки, светлая или тёмная тема.
- **Файл базы** — кнопка с текущим путём открывает системный выбор файла. При выборе нового файла туда копируется текущая зашифрованная база, а исходный файл сохраняется. Существующая база открывается без перезаписи. **По умолчанию** возвращает путь `%USERPROFILE%\.CHROME-APP-TOTP.vault`. После смены файла нужно войти паролем и при необходимости заново настроить автоматическое открытие или passkey.
- **Время жизни сессии** — 30 секунд, 1 минута (по умолчанию), 5 минут или «Вечная». Отсчёт начинается после авторизации; открытое окно и действия не продлевают его. Выбор сохраняется сразу и применяется к текущей сессии после закрытия окна, в котором изменена настройка. Для «Вечной» ключ защищается Windows DPAPI и позволяет открывать базу после перезагрузки ПК. Выбор конечного срока удаляет сохранённую копию ключа; файл всегда остаётся зашифрованным.
- **Ключ вместо мастер-пароля** — доступно при выключенном автоматическом открытии. Следуйте системному диалогу создания passkey. Нужен совместимый ключ доступа с поддержкой WebAuthn PRF: одного наличия Windows Hello или passkey недостаточно. Если выбранный вариант не поддерживает PRF, вход по мастер-паролю остаётся доступным.
- **Сменить мастер-пароль** — перешифровывает текущую базу. В режиме автоматического открытия потребуется текущий пароль. Старые резервные копии сохраняют прежний пароль, а passkey нужно привязать заново.

**Автоустановка кодов** по умолчанию выключена. Для её использования привяжите аккаунт через его шестерёнку к поддерживаемому сервису — Госуслугам, OpenAI или вашему Битрикс (обычный вход и админка) — и разрешите доступ к выбранному HTTPS-сайту. Привязки можно сохранять при выключенном режиме. Включите автоустановку в настройках и разрешите доступ к выбранным сайтам. Ожидание поля кода начинается после действия входа и длится до 15 секунд. После вставки кода кнопка продолжения нажимается однократно; на Госуслугах переход выполняет сам сайт. Кнопка **Отключить доступ ко всем сайтам** отключает автоустановку и отзывает разрешения.

## Резервная копия и перенос на другой ПК

Простейшая резервная копия — копия файла `.vault`. Закройте окна приложения после сохранения изменений и скопируйте файл из расположения, указанного в настройках.

Также в меню **Экспорт и резервная копия** можно выбрать аккаунты и формат **Зашифрованная копия JSON**. Такая копия защищена текущим мастер-паролем. Форматы JSON/TXT с открытыми ключами и экспорт QR содержат секреты без парольной защиты.

Для переноса базы:

1. Установите приложение и файловый помощник на другом ПК по инструкции выше.
2. Скопируйте файл базы в удобную постоянную папку.
3. В настройках приложения нажмите путь в разделе **Файл базы** и выберите перенесённый файл.
4. Введите мастер-пароль этой копии. Для добавления аккаунтов из экспортного JSON в другую базу используйте импорт через **QR из файла или скриншота**.

Для открытия перенесённой базы достаточно файла и его пароля. Автоматическое открытие и passkey на новом ПК настраиваются заново. Разрешения сайтов и оформление также проверьте в новом профиле Chrome.

## Обновление и перенос папки приложения

1. Сохраните резервную копию базы и убедитесь, что знаете её пароль.
2. Закройте окна Local 2FA Authenticator и замените файлы программы новой версией в прежней папке.
3. Если обновляетесь из исходников без готового `CHROME-APP-TOTP.Host.exe`, пересоберите помощник командой из корня приложения:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\native\Build.ps1
   ```

   Это важно, если старый EXE уже существует: `Install-Windows.cmd` собирает помощник только при отсутствии EXE.
4. Запустите `Install-Windows.cmd`, затем на `chrome://extensions` нажмите кнопку перезагрузки на карточке Local 2FA Authenticator.
5. Откройте приложение и проверьте, что видны ожидаемые аккаунты.

Если вы **перенесли папку программы**, обязательно запустите `Install-Windows.cmd` из нового расположения: регистрация помощника содержит путь к его EXE. В Chrome заново загрузите подпапку `extension` из нового расположения через **Загрузить распакованное расширение**. Обычная перезагрузка карточки не меняет сохранённый Chrome путь к папке. После этого проверьте путь к базе и открытие приложения.

Перенос папки программы сам по себе не переносит базу. Если переместили и файл `.vault`, выберите его новый путь в настройках.

## Если что-то не работает

| Симптом | Что сделать |
| --- | --- |
| «Не подключён файловый помощник» или «Не удалось запустить файловый помощник» | Запустите `Install-Windows.cmd` из текущей папки приложения под тем пользователем Windows, который запускает Chrome. Перезагрузите расширение и нажмите **Повторить**. |
| Установка не может собрать помощник | Проверьте наличие .NET Framework 4.x и полную распаковку папки `native`. Сохраните текст ошибки установщика для диагностики. |
| «Файловый помощник не ответил» | Если открыт диалог выбора файла, завершите или отмените выбор. Повторите действие; при повторении ошибки перезапустите Chrome и проверьте доступность папки приложения. |
| Файл базы перемещён, недоступен или повреждён | Выберите правильный файл в настройках. Для повреждённого файла используйте исправную резервную копию. |
| Камера запрещена | Разрешите камеру для страницы расширения в Chrome и доступ к камере в Windows. Используйте отдельное окно приложения; при запросе доступа оно может открыться автоматически. Альтернатива — импорт изображения QR. |
| Камера занята или не найдена | Закройте использующее её приложение, подключите камеру или выберите другую в списке. |
| QR не распознаётся | Держите его целиком в кадре, измените расстояние и освещение либо импортируйте исходное изображение. Для многочастного экспорта считайте все части. |
| Passkey не поддерживает PRF | Войдите мастер-паролем; подключите другой совместимый ключ доступа. |
| Не удалось открыть сохранённый ключ Windows | Войдите мастер-паролем и заново настройте автоматическое открытие на этом ПК. |
| Код не принимается сайтом | Проверьте дату и время Windows, выбранный аккаунт, алгоритм, число цифр и период кода. Попробуйте новый код после смены текущего. |
